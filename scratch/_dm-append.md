## 六、`CLARIFY` 与「立红」的加固经验（CHG-019 / CHG-020）

### 6.1 `CLARIFY` 的效率来自「先核实、再表态」

`CHG-019` 一次把 **6 条问题（含 3 条 P1）同日定稿**，靠的不是讨论，而是**每条都有硬依据**：

| 问题类型 | 依据形态 | 例 |
| :--- | :--- | :--- |
| 真源归属 | **因果链**（"这个值的输入来自哪里"） | `Q-046`：`REQ-004` 定等级由累计创作积分定级 + 积分的唯一来源在成长学院 ⇒ **加分的来源就是定级的真源** |
| 结构级迁移 | **绑定数**（改动的爆炸半径） | `Q-049`：`#modal-studio` 实测**合计绑定 10 处** ⇒ 一次性迁移风险高 ⇒ **两阶段** |
| 上游未落地 | **"用既有入口顶上，禁造临时结构"** | `Q-050`：分源池真源归 `SPEC-009`，过渡期沿用 `getComputeBalances` ⇒ 🔴 **临时结构会活成第二事实源** |

> 🔑 **可复用判据**：
> · **「谁持有真源」= 谁生产这个值的输入**（不是谁消费，也不是谁"更适合"）；
> · **「改不动的结构」= 绑定数 ≫ 1** ⇒ 默认答案是「**两阶段 + 保留兼容层**」；
> · **「缺一个上游时」** ⇒ 用**既有入口的最小能力顶上**，**绝不造临时的池 / 表 / 计数器**。

### 6.2 「立红」的做法（3 次实战，逐次加固）

**工序**：`spec.md` 的 SC → 编译成**可运行断言** → **先看它红** → 再实现。

**套件模板（照抄即可）**：
1. 头部注释：**逐条冻结契约**（签名 + 关键语义 + 边界）；
2. 最小 DOM 桩 + `vm` 沙箱（**按需补桩**：`location` / `localStorage` / `setTimeout` 同步执行）；
3. **两类计数**：`ok()` = 功能断言（未实现必失败）· `okInv()` = 不变量断言（未实现时**平凡通过**，**不计入进度**）；
4. 输出格式**必须**符合门禁契约（见 `PITFALLS-ARCHIVE.md` §M）；
5. `WB_VERBOSE=1` 打印**通过项**（用于复核平凡通过）。

### 6.3 🔑 🔴 「平凡通过」的加固手法（`CHG-016` 发现 3 项 → `CHG-020` 发现 **12 项**）

**判据（必须逐条问）**：**它是"做到了"，还是"什么都没做"？**

| 断言形态 | 未实现时会怎样 | 正确归属 |
| :--- | :--- | :--- |
| "某状态**不得变化**" | **必然平凡通过** | ⇒ `okInv`（不计入进度） |
| "A **等于** A"（同值、`0 === 0`、`-1 === -1`） | **平凡通过** | ⇒ 必须补**前置非空** |
| "查不到 ⇒ 失败"（靠"没有成功提示"判断） | 方法不存在 ⇒ 没有提示 ⇒ **通过** | ⇒ 必须**先证明"能查到"** |
| "目标可见" | DOM 桩 `hidden` **默认 false** ⇒ 通过 | ⇒ 必须**同时断言"其余不可见"** |

**三种加固写法（直接可抄）**：
```js
// ① 前置非空：后续断言全部挂在"确实做到了"之上
const reached = !!lesson && lesson.status === 'done';
ok(reached && Number(plan.progress) === Math.round((done / total) * 100), '...');

// ② 配对前置：先算"成功路径"，再用它作"拒绝路径"的前提
const reviewOk = Number(pts) === b3 + 5;        // 有效心得确实 +5
ok(reviewOk && blank !== true && Number(pts) === b, '...');   // 空白心得必须拒绝

// ③ 双向断言：既要"能打开"，又要"查不到时失败"
ok(openedOk && saidFail, '...');
```

**并注意**：**顺序有时要调换** —— `CHG-020` 中把「有效心得 +5」重排到「空白心得拒绝」**之前**，才能用前者作后者的前置。

### 6.4 「顺序陷阱」的识别方法（`CHG-020` 的 `plan.md` §4.3）

**识别问法**：**这条改动依赖"另一个东西已经就位"吗？**

| 陷阱形态 | 问法 | 正确顺序 |
| :--- | :--- | :--- |
| 改**真源的值** | "消费方现在读的是真源吗？" | ⇒ **先让消费方读真源，再改真源的值** |
| 改**字段语义** | "写入点存在吗？" | ⇒ **先有唯一写入点，再改字段语义** |

> 🔑 **通则**：**"值"的改动必须晚于"读取路径"的改动；"语义"的改动必须晚于"写入路径"的改动。**
> 若顺序反了，症状是"**看起来对但依据错**"（最难查的一类）。
