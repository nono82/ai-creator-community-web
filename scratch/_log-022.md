### 🔑 本轮最有价值的一件事：**13 项"平凡通过"的三类成因**（首跑 20/129 → 加固 4/126）

| 成因 | 实例 |
| :--- | :--- |
| **① 字段全缺 ⇒ 条件必然成立** | `A5`「所有 `integration` 取值均合法」—— 因为**所有工具都缺该字段**，筛出的"非法项"恒为 0 |
| **② DOM 桩默认值天然满足** | `C5`（`classList` 天然不含 `active`）/ `C11`（`hidden` 天然 `false`）/ `G3` |

**加固手法**：为每条「相等 / 不得变化」型断言**并入前置变量**（`r === true` / `reachedF` / `collapsed` / `reachedG` / `reachedH`），并把「源码级负向」断言移入 `okInv`（属不变量族）。
⇒ **与 `CHG-020` 的加固同法，但这次多了一类（①"字段全缺"）—— 之前没遇到过。**

### 🔑 第二件：`fresh()` 的**跨组污染**（靠追问"为什么 `C5` 会是绿的"发现）

`fresh()` 原来只重置 `hidden / innerHTML / innerText / textContent`，**未重置 `classList` 与 `value`** ⇒
- `value` 残留 ⇒ `H8`（"恢复后 Prompt 非空"）会**平凡通过**；
- `classList` 残留 ⇒ `C5` 会被 `B11` 给 `#modal-studio` 加上的 `active` **永久污染**。

⇒ 已在 `fresh()` 内重置 `value` / `classList` / `disabled`。
**⇒ 教训："通过项"本身也可能是缺陷的藏身处 —— 不只复核"为什么它是绿的"，还要问"它凭什么绿"。**
