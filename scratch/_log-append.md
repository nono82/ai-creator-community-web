### 🔑 本轮最有价值的一件事：**12 项"通过"逐项复核后，发现全是"平凡通过"**

立红首跑显示 **12/77**。若就此采信，会以为"已经有 12 项做完了"。逐项复核后：

| 被"通过"的断言 | 为什么它是假的 |
| :--- | :--- |
| `A11`（`points` 与 `learningPoints` 同值） | 加分未实现 ⇒ **两份都没动** ⇒ 同值 |
| `C4`（`progress` 按课节数重算） | 课节根本没完成，`progress` 本就没变 |
| `C6`（下一节置 `learning`） | `P1-L03` **本来就是 `learning`** |
| `C9`（失败调用不改数据） | 什么都没做 |
| `C11`（重复打卡不重复加分） | 同上 |
| `C12`（视频课未看够不得完成） | 同上 |
| `C14`（状态值域无中文） | 数据本来就没中文状态（**本质是不变量**） |
| `E11`（重复领证不重复加分） | `claimCertificate` 不存在 |
| `F2`（成就查不到显式失败） | 没有 Toast ⇒ 判据 `!saidOk` 为真（**判据过弱**） |
| `G3`（目标页可见） | DOM 桩里 `hidden` **默认 false** ⇒ 6 页全"可见" |
| `G7`（未知 id 不改现状） | 没实现 ⇒ 没改（**本质是不变量**） |
| `H10`（空白心得拒绝） | `submitCourseReview` 不存在 |

**⇒ 真通过 = 0 项。**

**加固手法（可复用）**：
1. **为每条断言补「前置非空」** —— 把"必须确实做到了 X"作为后续断言的前置条件：
   - `C3/C4/C5/C6/C7` 全部挂上 `reached = (目标课节.status === 'done')`；
   - `C9/C10` 挂上 `afterFirst === lp0 + 30`（首次打卡确实加了分）；
   - `C12` 挂上"存在成功路径"（否则"方法不存在"也会通过）；
   - `E11` 挂上 `claimOk`（单次领证确实 +100）；
   - `F2` 改为"**既要能打开、又要查不到时失败**"（先证明 `openedOk`）；
   - `H11` 重排到 `H10` **之前**，用 `reviewOk` 作前置。
2. **把本质是不变量的断言移入不变量组**（`C9` 并入 `I5`、`C14` → `I9`、`G7` → `G6[inv]`）。
3. **把与"必须真实变化"等价的断言合并**（`G3`+`G4` 合并为一条）。

⇒ 加固后 **0/77**。

> 🔑 **推广**：**任何"通过"都要问一句 —— 它是"做到了"，还是"什么都没做"？**
> 更细的判据：**"不得变化"型断言在未实现时必然平凡通过** ⇒ 它只能是 `okInv`；**"等于某值"型断言若该值在未实现时也成立（`0 === 0`、`A === A`）** ⇒ 必须补前置。

### 🔧 工具层：补齐「门禁输出格式契约」（同一问题第 2 次踩坑）

红灯套件需在**最后一行**输出 ` 通过：x/y 项功能断言（不变量断言 a/b 未计入）`，`gates.js` 的 `parseCount` 依 `/通过\s*[：:]\s*(\d+)\s*\/\s*(\d+)/` 提取 ⇒ 用于报出「已登记待实现 x/y 项」。

**发现**：`wb-identity-admission-verify.js` **早就有**这一行，而 `wb-content-asset-verify.js`（我上轮写的）**漏了** ⇒ 它的红灯进度被计为 `0/0`，红灯机制"单独报进度"的能力**静默失效**。
（`CHG-017` 我修的是**绿套**的「全部通过：N 项」格式，**漏了红灯期这一条**。）
⇒ 已给三套统一格式，并在 `tools/README.md` 增设「**输出格式是门禁契约的一部分**」小节，记录两次踩坑。
